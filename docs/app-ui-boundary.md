# 应用层 UI 调用边界

## 状态与范围

本文记录已确认保留的 UI 调用边界，按源码基线 `67e5bad` 核对并纳入版本管理。不代表已实施控件更新/绘制拆分，也不授权新的 UI 重构。

当前保留 framework/control 的控件生命周期。几何同步迁移见 [几何同步方案](scene-render-geometry-plan.md)，领域术语见 [context.md](../context.md)；本文不改变当前 UI 行为。

## 当前职责

源码路径相对 Rigid2DSimulation/。

| 位置 | 当前负责的工作 |
| --- | --- |
| current/common/SimulationApp | 调度输入归属收集、脚本、编辑器、场景状态更新、物理推进、几何同步、场景绘制及 UI，并处理脚本错误 |
| current/editor/SceneEditor | 解释场景编辑输入，管理选择、拖拽工具及创建工具，不承担控件事件处理 |
| current/ui/UserInterface | 组织菜单、底栏和浮动面板的遍历；作为应用层访问旧控件生命周期的统一入口 |
| framework/control | 控件命中、焦点、点击、文本编辑、布局和绘制；目前这些操作尚未完全分阶段 |
| current/ui 下的 Panel 及其控件 | 组装控件、同步应用数据显示，调用应用层业务入口 |

App 不自行遍历具体按钮，不读取控件的 chosen 等内部状态来执行业务；场景点击由 Editor 解释。保留 UserInterface::PreUpdate 和 UpdateAndRender 两个真实存在的入口，不用空包装伪装成已经拆好的 Update/Render。

## 保留的执行顺序

1. SceneCanvas、Editor、UI 收集输入归属；Editor 在拾取前应用待处理的创建配置，UI 内仍按现有规则排序浮动面板。
2. App 计算并通过 SetFrameDeltaTime 设置本帧时长，再调用一次无参脚本 Update，将时长发布到脚本作用域并执行脚本；之后处理音乐、暂停快捷键和删除清理。本帧时长不因脚本修改上限而重新计算。
3. Editor.Update 处理场景编辑输入并返回每帧拖拽快照；随后 App 处理脚本错误。
4. UpdateSceneState 更新场景分组、每帧拖拽作用和轨迹。
5. AdvanceSimulation 在未暂停且本帧时长非零时推进物理；App 再次处理脚本错误，随后 World.UpdateGeometry 无条件同步几何。
6. Renderer 绘制场景、连接和创建预览。
7. UI.UpdateAndRender 按菜单、底栏、浮动面板的顺序处理控件更新和绘制；App 随后处理 UI 操作产生的脚本错误。

此顺序描述现状，不是“整个应用已经具有纯输入、纯模拟、纯渲染阶段”的声明。

HandleScriptError 在存在脚本错误时暂停模拟，并将尚未消费的错误写入日志。它不会回滚之前执行的脚本副作用，也不会重新绘制已经完成的画面。

## 已知限制

- Button::Update 处理点击并调用 Render；Panel::Update 将背景绘制、子控件更新和滚动条更新放在同一个入口。只在 App 拆两个调用无法解决这种混合。
- 暂停按钮在第 7 阶段改变 isPaused，本帧物理已经推进；空格快捷键在第 2 阶段处理，两者生效时点不同。本轮保留，不借边界整理改变交互语义。
- UI 触发重置、物体脚本应用或显示模式切换时，当前场景已经绘制；变化不会追溯修改已经完成的场景绘制。
- 面板删除仍通过 Editor/World 标记对象，由后续帧的删除清理实际移除；本文不改变删除协议。
- 创建面板调用 Editor 的工具选择和配置请求入口，不直接创建世界对象；请求在下一次 Editor.PreUpdate、输入拾取之前应用。
- 时间标签等显示内容目前在模拟后读取数据。若将整个 UI.UpdateAndRender 提前，会同时提前显示数据采样并破坏场景与 UI 的绘制顺序。
- 控件尺寸、滚动布局及输入归属仍受现有生命周期制约；本文不尝试修复这些框架问题。

## 后续工作条件

只有明确授权 framework 重构时，才继续以下工作：

1. 打通控件和容器的独立 Render 遍历，保留背景、内容、滚动条及浮动面板的绘制顺序；先保持业务执行时点。
2. 将控件输入处理与显示同步/布局区分，保证一次输入只执行一次业务操作，显示数据在合适时点刷新。
3. 再决定 App 的新调度顺序。届时逐项确认暂停、重置、删除、脚本应用、窗口开关、文本焦点和点击穿透规则，不能仅将 UI.Update 整体前移。

按钮回调化是另一项可独立设计的工作，不是实现独立 Render 的前提，也不在本文中追加实施。[UI 回调化方案](ui-callback-refactor-plan.md)不因本文自动获准执行。
