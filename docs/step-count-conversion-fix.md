# 子步数量转换前校验

## 问题与修改

SceneScriptRuntime::SetConfig 原来通过 TryReadConfigNumber 将 DSL 的 double 直接写入 int 类型的 stepNum，随后执行 max(1, stepNum)。后者只能限制转换后的最小值，无法补救 NaN、无穷大或超范围数值到 int 的无效转换；读取函数也没有检查 DSL 类型。

本轮仅修改该字段的读取：先检查 num 类型、有限性以及 [INT_MIN, INT_MAX] 范围，再显式转换为 int。不调整通用配置工具、物理公式或其他字段。

## 保留的规则

- 范围内的合法小数继续向零截断，不新增严格整数要求。
- 转换后仍执行原有 max(1, stepNum)，因此范围内的零和负数继续调整为 1。
- 类型错误、非有限值或范围外的数值不写入 stepNum，沿用原有配置，并通过 wcerr 提示；不终止脚本或暂停模拟。
- 未提供字段时不读取新值，但保留原有最小值限制。因此若 C++ 调用方原本写入了小于 1 的 stepNum，SetConfig 仍会将它调整到 1；正常配置不受影响。
- 本次未新增性能上限：INT_MAX 以内的较大正整数仍可设置，不能据此声称任意配置都具有可接受的运行成本。

## 验证范围

- 正常整数、小数截断、零和负数最小值限制、INT_MIN / INT_MAX 边界。
- 边界之外、极大数、NaN、正负无穷以及非 num 类型被拒绝，旧配置保留。
- 字段缺省、其他配置字段独立生效、真实 DSL 调用与正确子步推进次数。
- 测试放在忽略的 x64/frame-time-check/，不提交；代码与本文经用户确认后一起提交。
