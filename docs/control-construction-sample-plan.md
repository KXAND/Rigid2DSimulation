# 控件创建接口示范：GlobalPanel

## 目标与范围

基于 `670ac88`，只迁移 GlobalPanel，减少手工创建、保存控件和拼接布局的代码。不引入 HTML、解析器或第三方 UI 框架，不推广其他面板。

原有横纵容器已经负责坐标计算。本轮不改变位置、间距、宽高、滚动、输入或更新/绘制顺序，只改变控件的创建和持有方式。

## 目标写法

```cpp
auto& saveRow = layout->AddRow();
savePathTextBox = &saveRow.AddTextBox(270);
saveRow.AddLocalizedButton(80, L"saveButton", SaveScene);
```

加载行同样组装，随后加入分隔线与详情。保存、加载业务仍由 GlobalPanel 定义；详情文字仍在按钮处理之后读取。

## 创建与持有

- 两种 ControlList 增加 Add，接收非空 unique_ptr 并持有子控件；返回引用，不另建所有权。
- 横向容器提供 AddTextBox、AddLocalizedButton；纵向容器提供 AddRow、AddSeparator、AddRichLabel。只提供本示范需要的便利接口，不添加通用模板或新布局机制。
- GlobalPanel 只持有一个根布局和两个借用的输入框指针，移除按钮、行、分隔线及详情的独立成员。
- 堆上的子控件地址不因容器内部 vector 扩容而改变；借用引用在 Clear 或所属容器销毁后失效。GlobalPanel 构造后不重建根布局，因此输入框引用在面板使用期间稳定。
- 本轮不修改其他面板；原裸指针列表继续服务尚未迁移的调用方，容器只销毁通过 Add 接管的控件，不销毁外部提供的控件。
- 使用 Add 的代码不直接修改 controls；它只作为原遍历算法的视图。其他面板的动态行仍沿用现有方式，此次不迁移。

## 清理规则

Clear(App&) 先对列表执行 Discard，释放焦点、取消待处理输入，再清空遍历视图并销毁所持有的控件。对外部借用的控件只执行 Discard，不销毁。

普通析构只释放所有权，不持有 App 引用以隐式调用 Discard；沿用 Control 原有的销毁前清理约定。面板关闭仍由 FloatPanel::Hide/Discard 递归清理，不销毁布局，可以再次打开。

本示范不提供单个子控件删除或动态隐藏 API，不允许在遍历中的点击回调里 Clear 正在执行的容器；这些能力留待实际迁移动态面板时单独设计。
