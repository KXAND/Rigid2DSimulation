## 2. 数据与接口

源码路径相对 Rigid2DSimulation/current/。

| 位置 | 修改 |
| --- | --- |
| rigid/Body.h | 删除 track，物理对象不再保存显示历史 |
| editor/SceneEditor.h/.cpp | 私有 unordered_map<Body const*, vector<Vector2>> tracks；ClearTrack(Body const&) 删除指定记录；GetTracks() 返回集合的 const 引用 |
| render/SceneRenderer.h/.cpp | SceneRenderContext 持有轨迹集合的 const 引用，RenderBody 按当前 Body 地址查询，在原位置绘制；不依赖完整 SceneEditor |
| rigid/Group.h/.cpp | Warp 增加必传的同步 onBodyWarped(Body const&) 回调，原四处 track.clear() 原位改为通知 |
| rigid/PhysicsWorld.h/.cpp | Advance 增加并转发上述回调，不保存，不引用编辑器或轨迹类型 |
| common/SimulationApp.cpp | 回调仅调用 editor.ClearTrack(body)；绘制上下文引用 editor.GetTracks() |

不新增事件总线、管理器、生产文件或通用模板。通知只报告越界处理，不命名为轨迹清理；回调只能同步维护外部记录，不在通知中修改世界集合或触发嵌套推进。

tracks 的键不拥有 Body。只有采样才建立记录，清理用 erase；读取不用 operator[]，不凭绘制建立空记录。只读引用只在同步绘制期间使用，不跨帧缓存迭代器或元素引用。

## 3. 行为和生命周期

1. 采样保持 UpdateBody 中原位置：拖拽处理后、连接创建端点处理前、物理推进前。选中、开启显示且未暂停时追加当前位置。
2. 未选中或关闭显示时在原逐物体更新位置清理；选中且暂停时保留历史。
3. 不将逐物体记录合为一条当前选择的轨迹。同一帧从先遍历物体切换到后遍历物体时，旧轨迹可能短暂共存，必须保留。
4. ClearSelection 只清选择，不提前清历史；切换、关闭轨迹在 UI 阶段发生时也不提前追溯处理。
5. PrepareForDeletion 在实际删除之前移除所有待删除物体的记录；ResetInteraction 在 ClearObjects 之前清空全部记录，防止残留地址被新对象复用。
6. Warp 每次原坐标加减之后立即同步通知，再执行下一物体/方向；保留固定及拖拽物体排除规则。即使多个方向被连续执行也不合并通知，不额外同步几何。
7. 渲染仍在每个物体原有轨迹位置绘制，颜色、深度、点顺序不变。世界对象之外的新创建预览没有历史；相同物体身份的查询读取同一条记录。
8. 轨迹仍不写入存档。加载重置场景后不恢复历史。复制 Body 的物理数据不再复制编辑器轨迹，生产创建/加载不依赖该复制行为；本地历史夹具需显式提供对应轨迹，不能把测试内构造方式误当成生产功能。

## 4. 实施与验证

- 共 10 个生产文件，作为一个实施批次，不按文件或函数拆提交。
- 原交互、绘制及 Group Warp 对照端保留独立的旧轨迹规则；实际端通过 SceneEditor 查询记录。
- 逐帧比较轨迹点：正常采样、暂停/继续、开关、两种遍历方向的选择切换、空白取消选择及 UI 阶段改变选择。
- 检查删除、重置、无所有权延长及地址复用；清理不改变选择、拖拽或物理结果。
- 对照四个越界方向、连续多个方向、固定/拖拽组及空组，检查通知位置和清理结果。
- 比较轨迹绘制及预览的 RGB/alpha/depth 缓冲；复跑创建、属性、脚本及存储回归。
- Debug/x64 构建；C++ 使用 UTF-8 BOM、CRLF、4 空格；git diff --check。
