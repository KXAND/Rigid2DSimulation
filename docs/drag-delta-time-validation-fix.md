# 拖拽时长校验修正

## 决策依据

基线 84f1130，分支 fix/app-logic。

默认时长上限为 0.05，正常主循环先更新计时再执行应用更新；暂停不会将时长置零。但 SetConfig 原先可将 maxRealDeltaTime 写成零，随后 min(maxRealDeltaTime, measuredDeltaTime) 得到零。物理推进跳过，普通/整体每帧拖拽仍除以该时长，可能污染物体速度。

本轮按用户确认选择“配置入口拒绝非法值 + 计算入口安全退出”，不增加任意最小帧时长。

通用决策方法：

1. 先确定数据契约：这里的时长必须为有限正数；零上限不是暂停指令。
2. 找到不同职责的边界：配置解释负责拒绝非法设置并反馈；计算模块负责保证无效输入不修改物体。后者也可能被测试、未来入口或实际计时结果直接调用。
3. 比较失败策略的语义：拒绝保留上次合法设置，跳过不产生本次作用；clamp 却猜测了一个不存在的时间，可能产生巨大速度并掩盖错误。
4. 限定正常路径：所有有限正时长沿用原公式和运算顺序，不把防御性处理变成拖拽模型调整。
5. 用测试证明契约，而不只验证“不崩溃”：无效输入时状态不变；合法输入与旧实现一致；输入释放不受计算跳过影响。

不是所有数值都应一律拒绝而不 clamp。只有业务本身定义饱和行为（例如音量限制在区间内）时，clamp 才有明确语义；不能仅为避开除零随意设下限。

## 实施范围

源码路径相对 Rigid2DSimulation/。

- script/SceneScriptRuntime.cpp：仅对 maxRealDeltaTime 单独校验类型为 num、值有限且大于零。校验成功才赋值；失败保留原值，向 std::wcerr 报告字段名和合法范围。字段缺失不修改；同一配置中的其他字段仍按原规则应用。这里没有引入整份配置事务、错误弹窗或异常框架。
- rigid/BodyDrag.cpp：在公共计算路径 ApplyDrag 内，目标匹配后、任何公式执行前检查 realDeltaTime 和 stepDeltaTime 均为有限正数；否则直接返回。每帧入口将同一时长传给两个位置，子步入口检查两者。
- rigid/BodyDrag.h：明确无效时长不修改物体的契约。即使 Force 的公式仅使用 stepDeltaTime，子步入口仍统一要求两个时长有效；每帧 Force 继续不施力。
- App 的 min 上限截断、暂停判断和 DragTool 的输入处理不改。跳过计算不跳过输入，因此无效时长下仍可释放或取消拖拽。
- 不覆盖其他配置字段校验、正时长极端数值的溢出、非法质量/惯量等问题，不修改物理算法或全局计时。

## 验证

修正前已复现：非法配置覆盖原值，零时长拖拽改变物体状态。

修正后验证通过：

- Debug x64 / Win32 构建通过，使用独立 TargetName，不修改 .vcxproj.user。
- 58 项脚本/配置测试通过，其中 20 项覆盖时长配置：零、负零、负数、正负无穷、NaN、错误类型、字段缺失、合法小正数、其他字段继续应用及真实 DSL 调用；拒绝时实际输出错误说明。
- 216 次非法时长计算检查通过：四类物体、三种拖拽方式、六种无效值，分别检查每帧时长、子步入口的帧时长及子步时长。六组释放检查证明跳过计算不阻止输入释放。
- 正常路径与旧实现对照通过：256 组场景、1280 次输入/每帧比较、3840 次子步比较，包含固定物体回退、快照独立性、首次按下及释放。
- 三个 C++ 文件保持 UTF-8 BOM、CRLF、空格缩进；git diff 检查通过。
