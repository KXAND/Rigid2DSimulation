# 第二步：统一编辑输入阶段

## 目标与边界

接续 scene-deletion-rules-plan.md 和 drag-input-calculation-separation-plan.md。
本步完成 Editor 的统一输入入口、Creator 调度归属和拖拽数据交接；不改三种拖拽公式、已有子步数量或 UI 框架。
不采用 UpdateBeforeSimulation / UpdateAfterSimulation 两次编辑器更新。

## 实施映射

源码路径相对 Rigid2DSimulation/。

| 现状 | 本步修改 |
| --- | --- |
| App 询问 SceneCanvas 是否空白点击，再清除选择 | SceneEditor::Update 接收画布身份，在最终输入归属为画布时处理空白点击；删除 IsEmptyAreaClicked |
| SceneEditor::UpdateBodies 同时解释输入、修改刚体、采样轨迹 | 替换为 Update，返回 BodyDrag 每帧作用快照；不执行拖拽公式，不采样轨迹 |
| App 根据 editor.mode 单独调用 Creator::Update | Editor 遍历现有物体、通知工具后，在同一个 Update 内调用 Creator::Update；避免遍历容器期间新增对象 |
| 拖拽工具返回数据后立即在 Editor 修改 Body | App 将返回值交给场景状态更新阶段，调用 rigid/BodyDrag 的每帧计算；子步继续使用持续拖拽快照 |
| 轨迹在逐物体输入逻辑中采样 | 提取 RecordTracks，只负责轨迹记录/清理，在每帧拖拽作用后、物理推进前调用；不是第二次输入更新 |
| Renderer 接收 Creator，预览端点由 Creator 在推进后写入 | 新增 CreationPreview 借用视图：物体、连接、连接局部锚点和鼠标目标；Renderer 用当前端点物体姿态换算绘制位置，不修改工具或预览连接 |
| App 直接读取 DragTool、按创建模式决定是否绘制预览 | Editor 提供 GetDrag / GetPreview；非创建模式返回空预览，App 不选择具体工具 |

## 帧顺序

1. 保留现有 PreUpdate 输入归属收集、脚本更新、全局快捷键和删除清理。
2. 计算 realDeltaTime，更新脚本帧时间参数。
3. Editor.Update：解释选择、删除、拖拽和创建输入；确认创建并返回本帧拖拽数据。
4. UpdateSceneState：World.Prepare（包含新对象和新连接），应用每帧拖拽，Editor.RecordTracks。
5. AdvanceSimulation：原有物理子步；Body.Step 后应用持续拖拽数据，再更新几何。不读取输入、不调用工具。
6. 绘制场景底图、物体和只读创建预览；最后保留 UI.UpdateAndRender。

BodyDrag 的本帧快照和持续快照不能合并：首次按下只有持续快照，释放帧只有最后一次本帧快照。暂停时仍执行原有普通/整体每帧作用，Force 不执行子步就不施力。所有数据仅当帧同步使用，不排队、不延后一帧；删除清理先于数据产生。

## 明确的时序变化

- 创建从物理推进和物体绘制之后，移到输入阶段。新物体当帧参与模拟和绘制；暂停时也当帧可见。
- 新连接的初始长度、钉子的固定位置取确认输入时的物体姿态，不再取本帧推进后的姿态。World.Prepare 必须在创建之后，确保新连接参与分组。
- 连接预览仍跟随推进后的物体：Renderer 用局部锚点实时换算，不需要再次更新 Creator。
- 轨迹仍在每帧拖拽之后、模拟之前采样；选择也在采样前统一确定，不再受被选物体在遍历容器中的先后顺序影响。
- 场景绘制集中到推进之后；调试文字读取这一阶段最新的脚本调试内容。

这不是完全等价搬迁，不用旧创建帧摘要宣称行为完全不变。拖拽数学和输入优先级保留，创建时序按上述新约定验收。

## 尚未包含的第三步

PreUpdate 仍是框架的输入归属收集机制，UI.UpdateAndRender 仍混合控件逻辑和绘制，RenderObjects 仍刷新派生几何。因此本步完成不等于全应用已经形成纯输入、纯模拟、纯渲染三阶段。第三步另行设计；不修改 UI 回调体系、DSL 求值问题或拖拽手感。
