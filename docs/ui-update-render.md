# UI 更新与绘制分阶段

`UserInterface::UpdateAndRender` 替换为 `Update` 和 `Render`。为真正分离而非仅改名，`Control` 增加虚函数 `Render`，现有控件的 `Update` 不再调用绘制；容器、代理和面板分别向子控件转发两个阶段。隐藏浮动面板不更新、不绘制，原有面板绘制顺序保持不变。

App 的帧顺序为：确定输入归属 → 快捷键与 UI 回调 → 原有脚本和音乐更新 → 编辑工具更新 → 场景清理、准备和拖拽应用 → 物理推进 → 世界绘制 → UI 绘制。音乐仍由原有 `UpdateMusic` 更新，静音按钮可以影响本帧采样。本分支不包含音乐模块拆分或脚本停用，可独立检查和合并。

按钮、复选框、文本提交等操作回调只在更新阶段执行；绘制阶段不重复执行操作。文本框回车提交及释放焦点也在绘制前完成。UI 的文本和布局仍在更新阶段同步，因此物理推进后产生的数值、编辑器新选中的对象会在下一次 UI 更新时反映；本轮不引入额外的数据绑定或展示刷新阶段。

UI 重置/载入可能发生在本帧拾取之后，因此 `Reset` 在销毁旧场景对象前清除它们的输入归属。删除仍在场景状态阶段集中处理，不在控件绘制时修改场景。
