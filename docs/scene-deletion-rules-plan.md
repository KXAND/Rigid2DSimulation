# 场景删除规则收紧

## 范围

基线 ea92c52。本轮只执行删除流程第一步，待用户验收后再提交。不推进输入分发、工具调度或更新/渲染解交错。本文替代旧关联方案中“清理阶段才传播连接删除标记”的安排，保留历史文档。

## 规则与修改

源码路径相对 Rigid2DSimulation/。

- PhysicsWorld::RequestBodyDeletion 在标记 Body 时同时标记其全部连接，重复请求保持幂等；不立即解除关联、释放对象或改变容器顺序。
- 移除 MarkDeletedConnections 及调用。App 的清理阶段先遍历待删除物体及连接，调用 inputOwners.Remove 释放输入归属，再执行 editor.PrepareForDeletion(inputOwners)，最后 world.RemoveDeletedObjects，阶段位置不变。
- AddConnection 在任何容器变更前拒绝待删除端点，沿用 invalid_argument；拒绝重新登记已标记的 Body/Connection，不提供复活或兼容入口。
- SceneEditor::PrepareForDeletion 只接收 InputOwners&，清理自身选择、悬停、拖拽、轨迹，并委托 Creator 清理创建引用；不再遍历 World 或承担世界对象的输入归属清理。保留 InputOwners 参数仅用于取消 Creator 时释放工具自身的输入归属。
- App 协调跨模块删除生命周期，InputOwners 清理输入引用，Editor 清理编辑状态，World 解除关联并移除对象。本轮不引入删除管理器或事件系统，不重新拾取或把同一点击转发给下层对象。
- Creator::PrepareForDeletion(InputOwners&) 检查两个端点；任一待删除则调用现有 Discard，取消本次创建及预览，不影响无关创建。OnBodyPressed/OnBodyReleased 不接纳已标记端点。
- RemoveDeletedObjects 显式区分“解除两端反向关联、移除连接、移除物体”。保留 erase-remove 算法，以命名迭代器表达新逻辑末尾，谓词使用 const&，不改成逐个 vector::erase。
- 实际移除时再次设置 isSceneChanged，避免删除请求与移除之间调用过 Prepare 后，分组仍引用已移除对象；仍在原 Prepare 阶段重建，不改变物理求解。

同步标记、拒绝待删除端点登记及取消失效创建属于本轮明确的行为变化。不改变正常拖拽/创建算法、鼠标和面板的删除触发方式、暂停行为、实际移除时机、存档格式或 DSL。

## 验证

状态：已实现并完成自动验证，经用户确认，代码与本文一起提交；第二步和第三步另行讨论。

- 同步级联标记、自连接、平行连接、重复请求、直接删除连接、容器保留顺序。
- 待删除端点和已标记对象登记拒绝，失败不留下部分关联。
- 编辑器选择/悬停/拖拽/轨迹、输入归属与创建端点清理；无关创建不取消；清理后可重新创建。
- 删除请求后先 Prepare 再清理的分组重建；暂停和运行路径。
- 新增规则检查通过：同步级联与拒绝登记不产生部分关联、实际移除重新使分组失效、空清理不触发分组重建、输入归属按对象清理且保留无关归属、保留容器元素顺序。
- 用户确认职责调整后，已将世界对象的输入归属清理移至 App；测试验证 Editor 单独清理不移除世界对象输入归属，随后协调阶段正确移除。为避免构造 App 加载窗口、字体及音频，本地协调测试复用当前 RemoveDeletedObjects 函数体，不替代完整 GUI 帧循环验收。删除/关联/存档及拖拽回归已重跑通过。
- 创建生命周期检查通过：激活前及预览期间的端点删除、两端分别删除、取消后重启、无关物体删除不取消连接/方框创建、已标记物体不能成为连接/钉子的创建端点。
- 关联/存档回归通过：64 组关联图（含自连接、平行连接和重复请求）、4 组删除入口/暂停组合、连接拆组、16 个内建场景、7 种创建模式及 32 次连接/钉子操作、16 次存储往返。
- 正常创建 224 组场景、1792 帧与已有基线一致；拖拽 512 组场景、4096 帧与拆分前基线一致。对照包含数值状态和绘制缓冲摘要，不声称本轮改变的删除标记时机与旧实现一致。
- Debug x64/Win32 构建通过，使用独立输出名。测试位于忽略的 x64/，不提交；未执行人工 GUI 验收。
- 七个源码文件均为严格 UTF-8 BOM、CRLF、无 Tab 或替换字符；git diff --check 通过。未改物理公式、工程配置或既有草案。
