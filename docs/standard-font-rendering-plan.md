# 标准字体渲染实验

基线：36ea311。分支：feat/standard-font-rendering。目标是替换手工逐字 .tile 字库，解决当前中文界面缺字。用户已确认提交本轮实现，代码、字体资源与本文一起提交。

## 方案

- 随项目附带 Google Fonts 的 Noto Sans SC TrueType 字体及原始 OFL 许可，不要求用户安装字体，不分发 Windows 系统字体。
- 使用现有 Windows 平台的 GDI 后端，以进程私有方式注册字体，不修改系统字体安装状态。按字符懒加载灰度位图并缓存，不逐帧读取字体文件。
- Font 独占字体与设备上下文资源，禁止复制，初始化失败或析构时释放资源。
- 字形区分位图、相对基线的位置和横向前进距离；不再把图片宽度当作文字宽度。
- 保持默认 20 像素行高和现有 CPU screen 绘制路径；文字覆盖率做灰度混合，不再仅判断透明或不透明。
- 绘制、测量、换行、文本框删除时的横向偏移、光标命中统一使用字形前进距离。
- TextBox 退格时读取实际被删除的前一个字符的宽度，而不是光标后的字符；这是此次变宽字形接入中的配套修正。
- 空格仅贡献前进距离；GDI 返回零长度位图时不读取位图数据。
- 不保留旧字库加载分支；清除无调用的随机文字接口和手工字符表。旧 .tile 资源暂不批量删除，但运行时不再读取。

## 资源与失败边界

- 优先从现有资源工作目录加载 fonts/NotoSansSC.ttf，也支持从可执行文件目录加载；构建时复制字体及许可到输出目录的 fonts/。
- 验证实际选中的字体族，拒绝 GDI 静默替换为不相干的系统字体。
- 未覆盖的字符使用字体内的替代字形；测试必须检查本地化文本全部字符均由真实字形覆盖，不能把替代方框算作通过。
- 字体文件丢失或初始化失败时明确提示并结束启动，不继续展示全空白界面。
- 本轮覆盖中文 BMP 字符、英文、数字和常用标点。保留现有按字符换行；不引入复杂文字塑形、emoji、UTF-16 代理对编辑或 GPU 字体图集。
- localization.txt 仍用 GBK，C++ 使用 UTF-8 BOM、CRLF、空格缩进。不修改物理、脚本、UI 输入调度或 .vcxproj.user。

## 依据

- [Google Fonts 的 Noto Sans SC](https://github.com/google/fonts/tree/main/ofl/notosanssc)：原始字体文件及许可来源。
- [GetGlyphOutlineW](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-getglyphoutlinew)：灰度位图行按 DWORD 对齐，GRAY8 的覆盖率为 0 至 64，需转换为 0 至 255。
- [GLYPHMETRICS](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/ns-wingdi-glyphmetrics)：使用字形原点及 cell advance 放置文字。

## 验证

已通过 Debug x64 / Win32 构建，两种输出目录均包含字体及许可。

- 本地回归 1299 项全部通过，其中全量本地化文件覆盖 372 个不同字符，无替代字形；此前缺失的中文字符另行覆盖。
- 覆盖灰度混合、深度遮挡、边缘裁剪、绘制与换行度量一致、光标命中、文本框退格、缓存复用、多字号、重复初始化、缺失文件、可执行目录回退加载以及 GDI 对象释放。
- 实际 SimulationApp 创建面板交互检查 58 项全部通过；导出中英文 CPU 画面并检查，文字正常显示、创建面板布局可用。
- 保留原按字符换行行为，英文长单词仍可能跨行，不在此次字体替换范围内。

尚需用户通过 VS 启动后检查实际显示效果及日常文字编辑手感。本次字体增加约 17.8 MB 原始资源，不保证 BMP 以外或字体未收录字符的覆盖。
测试和渲染图放在忽略的 x64/，不纳入 Git。
