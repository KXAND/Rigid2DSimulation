# 命名与宏迁移计划

## 1. 目的与边界

本文是 `docs/code-style.md` 的执行清单，不定义长期规则。目标是按小提交将全库迁移到统一风格；每个提交必须保持可构建、可审查，并遵循 conventional commit。

迁移不保留旧 C++ 或项目 DSL 名称兼容层。项目自定义 DSL 的函数名改为 PascalCase，变量和配置键改为 lower camel；所有 C++ 注册点、读取点、项目脚本和示例场景必须同时更新。脚本语法和 `.rigid2d` 二进制布局不变。

本计划只做风格和可读性整理：不修改物理逻辑、运行时行为、资源生命周期、调用顺序或序列化可靠性。

## 2. 已完成项

- 随机数相关 C++ 函数已统一为 PascalCase，并修正 `Radom` 拼写。
- 配置读取辅助函数已统一为 PascalCase。
- `framework/parse/var.cpp` 的参数求值简写已改为具名局部 lambda。
- `current/ui` 的 `cur`、`bsel`、`pcsel`、`par` 等上下文宏已清理。

## 3. 迁移批次

### 3.1 文件名与项目引用

- 将源文件和头文件改为 PascalCase，移除 `fpn_*`、`pn_*`、`dvec`、`vptr`、`app_wv`、`draw_comp` 等缩写或下划线命名。
- 每次文件重命名同步更新 `#include`、解决方案和项目文件引用。
- 文件重命名按目录提交，避免与内容重构混在同一提交。

### 3.2 命名迁移

- 以 `framework`、`current/common`、`current/rigid`、`current/ui` 为批次，统一类型、函数、成员、参数和局部变量命名。
- 清理 `Body`、`Shape`、UI 控件和绘制代码中的含义不明缩写。
- 将项目 DSL 的函数名、配置键和作用域键改为相应的 PascalCase 或 lower camel，并同步更新脚本与示例场景。
- C 标准库、Windows SDK 与第三方 API 标识符不改名。

### 3.3 基础宏清理

- 删除 `utils.h` 中的 `tw`、`ptr`、`msh`、`mkp`、`rep` 等别名或控制流宏。
- `mkp` 逐调用点改为显式 `std::make_shared<具体类型>(...)`；不得以泛型赋值模板继续隐藏构造类型。
- `frd`、`fwt`、`frds`、`fwts`、`frdv`、`fwtv` 逐调用点展开为明确读写语句。
- 序列化展开后局部文件句柄使用 `file`；长度变量按上下文使用 `size`、`<对象>Len` 或 `cnt`。不得改变读写顺序、类型或二进制布局。

### 3.4 绘制算法宏清理

- `framework/draw/draw_px_seg.cpp` 的 `TMP` 改为同文件匿名命名空间的普通私有函数，明确表达线段端点裁剪。
- `framework/draw/draw_tri.cpp` 的 `EdgeCut` 改为同文件匿名命名空间的普通私有函数，以返回值表达原宏的提前返回语义。
- 不使用模板，不移入 `utils.h`，不改变算法输入、计算顺序或输出。

### 3.5 排版、包含与注释

- 按模块迁移为 4 空格、CRLF、Allman 大括号、单条独立语句一行和完整控制流大括号。
- 调整包含顺序，并补齐直接依赖的头文件。
- 删除重复或无价值注释；保留并整理说明原因、约束或非显而易见影响的中文注释。
- 排版提交不混入命名、宏或算法私有函数迁移。

## 4. 提交与验证

- 每个提交只覆盖一个目录、一个命名主题或一种宏类型。
- 文件重命名、命名迁移、宏替换和纯排版分别提交。
- 提交前检查 GBK、CRLF 和无意的全文件格式差异。
- 每批执行相关文本搜索，确认旧名称或旧宏已无项目内引用。
- 每批至少执行 `Debug|x64` 构建；DSL 改名批次还要验证项目内脚本和示例场景的全部引用。

建议提交类型：`docs:`、`refactor:`、`style:`；提交信息遵循 conventional commit。

## 5. 明确不做

- 不改变脚本语法。
- 不改变 `.rigid2d` 二进制布局或修复其可靠性问题。
- 不改变物理计算、条件、循环边界、求值次数、资源生命周期或调用顺序。
- 不做无关的文件、类或函数拆分。
- 不保留旧名称兼容层。
