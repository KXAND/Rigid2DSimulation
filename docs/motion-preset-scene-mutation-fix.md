# 运动预设的场景修改限制

## 目标与边界

运动预设在 PhysicsWorld 遍历物体、执行子步时求值。此时 CreateBody 向同一物体容器追加元素，会使遍历迭代器失效；其他场景构造、配置操作也会在推进中途改变场景结构或规则。

本次只建立场景修改的执行边界，不更改预设公式、采样次数、子步数量、DSL 语法和参数数量规则。不将运动预设定义为完全纯函数，不处理全局变量写入、共享 Value 别名或随机数的副作用。

## 调用规则

| 执行场合 | 场景修改函数 |
| --- | --- |
| 场景初始化、显式应用脚本、无错误时的每帧 Update | 保留原有调用能力 |
| 位置、角度、角速度运动预设，包括其嵌套函数和别名调用 | 禁止 |

禁止的入口为 SetCreator、CreateBody、CreateConnection、SetConfig、Boundary、Gear、Strand、Necklace。Box、Ball、Parallelogram、Trapezoid、RegularPolygon、Cross、FramedBox 仅构造形状配置，仍允许调用；GetBodyCount 和数学函数不受本次限制。

SceneScriptRuntime 在执行预设脚本期间设置 isExecutingMotionPreset 标记，以 MotionPresetExecutionScope 作用域对象保证正常返回和异常退出均恢复此前标记。该标记覆盖整个预设执行阶段，包括嵌套函数调用，不仅是单个表达式求值。上述八个原生函数进入函数体后首先检查标记，先于参数检查及实际副作用。检查绑定在函数实现中，不依赖脚本文本或调用名，因此别名及间接调用不能绕过。解释器仍先求值实参；实参中的受限调用同样受到检查。

以后新增能修改世界、编辑器或 App 配置的 DSL 原生入口，必须在函数体开始处调用 RequireSceneMutationAllowed，不能只在直接创建物体的函数中检查。

## 违规后的行为

1. 受限入口抛出 ScriptError，立即终止当前求值，调用之后的脚本语句不再执行。
2. ApplyMotionPresets 捕获错误，记录预设类型和被禁止的函数名。异常不穿出 Body::Step，不打断物理遍历。
3. 错误保留期间跳过后续运动预设及自动脚本 Update。当前帧剩余的普通物理推进仍完成；App 在推进后暂停、在场景背景显示错误，并通过既有 AddLog 记录一次。未修正时不能仅通过暂停按钮绕过错误继续推进。
4. ResetScope、显式执行场景脚本完成、重新应用物体脚本完成时清除错误，允许重试。此操作不会自动取消 App 暂停；用户恢复运行后若问题仍在，将再次报告。

不是事务回滚：当前帧之前已执行的物理计算、成功应用的其他预设以及允许的 DSL 全局写入不会撤销。位置和角度预设仍在两次采样成功后才写入对应物理量，第二次采样违规不会写入半份该预设结果；若位置预设成功而随后角度预设失败，已应用的位置保留。

## 实现范围

- framework/parse/ScriptError.h：最小脚本错误类型，只承载消息，不引入参数数量校验。
- current/script/SceneScriptRuntime：执行标记、八个入口守卫、预设异常边界、错误查询与单次消费、重试时清理错误。
- current/common/SimulationApp：在推进前后处理错误，保持暂停并显示、记录原因。
- VS 项目文件：登记新增头文件。

采用已保存 DSL 契约方案中的 ScriptError、GetError、ConsumeError 接口形态，不恢复整份 stash。后续恢复 stash 时须合并新错误类型及错误边界，而不是重复定义；同时保留本次原生函数守卫、预设执行标记和此前帧时长、Creator 修复。当前诊断消息仅由固定预设名称和固定原生函数名称组成，不附加用户脚本文本。统一日志策略仍是后续任务。

## 验证计划

- 三类运动预设分别覆盖八个受限入口；直接、别名、嵌套调用均须终止且不改变场景或工具配置。
- 第二次采样才违规时，对应预设的物理量不写入；错误之后的脚本语句不执行。
- 错误只消费一次；错误保留时不再自动执行预设和 Update；显式重试及重置清除错误，执行标记不泄漏。
- 合法预设保持原有采样时点及计算结果；形状构造、查询、数学函数仍可用；场景初始化及 Update 仍可创建物体。
- 真实 PhysicsWorld 推进中违规不改变遍历容器、不抛出到推进外部，完成本帧时间推进。
- Debug x64 / Win32 构建、既有脚本与 Creator 回归、UTF-8 BOM / CRLF / 空格检查。测试放在忽略目录，不纳入提交。
